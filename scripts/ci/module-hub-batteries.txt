# ── POR QUÉ EXISTE ─────────────────────────────────────────────────────────────────────────
# hub#1264 saca del hub los e2e que afirman comportamiento de UN MÓDULO y los devuelve al repo de

# lo que lo hizo caro: ningún rojo avisó de que esa cobertura había dejado de ejercitarse.
#
# ── CÓMO SE EDITA ──────────────────────────────────────────────────────────────────────────
# Un slice de hub#1264 hace las dos ediciones EN LA MISMA PR:
#
#   1. BORRA la línea del e2e en `scripts/ci/kernel-e2e-targets.txt`, y
#   2. AÑADE aquí la batería que hereda esa cobertura.
#
# Ese par de ediciones es el acto revisable. Un borrado que no apunta a nada comprobable es
# exactamente cómo se perdieron los 391 de `services`.
#
# 🔴 LO QUE ESTA LISTA NO DICE. Dice que la batería ESTÁ donde el slice prometió. NO dice que se
# ejecute: hoy NINGÚN gate corre `erplora test --against-hub`, y hub#1381 sigue abierta para eso.
# Un verde aquí se lee «la batería está donde dijeron», nunca «la batería pasa». Los tres
# bloqueos medidos del corredor están en hub#1381.
#
# El formato es `<module-id>/<ruta de la batería dentro del módulo>`.
